# 使用与交接

## V0.0.3 历史回填

- `run_history_backfill` 是一次性显式操作，不加入每日计划；与 `run_backup` 共用互斥锁。
- `dry_run: true` 只返回本次有界扫描发现的数量，不推进历史状态。
- 正常调用默认最多选择 100 条并最多扫描 20 页。返回
  `history_limit_reached` 或 `history_scan_limit_reached` 时可继续调用；只有
  `history_complete: true` 才表示接口已明确到达当前可查询历史终点且已发现页面均处理完。
- 历史页面未全部处理完时保持原页游标，重试不会跳页；每日增量游标不倒退。
- 目标 HAOS 已部署 manifest `0.0.3`；真实历史调用已返回 `history_complete: true`，
  最终历史 dry-run 为零待处理，每日增量 dry-run 也保持健康。

## V0.0.2 目标发现

- 优先使用 Xiaomi Miot 已加载云会话的设备列表，并按内存设备编号合并同一物理设备。
- 设备列表没有目标型号时，才使用 Xiaomi Miot 已加载实体索引；实体云对象必须属于
  已加载会话。
- 无目标返回 `TARGET_MATCH_NONE`，多个不同目标返回 `TARGET_MATCH_MULTIPLE`。
- 固定错误码、服务响应和诊断均不包含设备编号、账号字段或认证值。

## 安装前

1. 确认 Home Assistant 中的 `hass-xiaomi-miot` 已登录且能正常读取设备。
2. 确认目标设备型号；默认实现只对 `xiaomi.lock.s1` 的事件发现路径有实际观察。
3. 在 `/media` 下准备可写父目录。NAS 网络存储必须由用户事先在 Home Assistant
   中配置，本集成不创建共享或挂载。
4. 确认目标文件系统支持同目录硬链接与 `fsync`；否则无覆盖原子发布会返回
   `ATOMIC_PUBLISH_UNAVAILABLE` 或 `OUTPUT_SYNC_FAILED`。
5. 备份 Home Assistant 配置，并记录当前可回退版本。

## 建议验收顺序

1. 安装集成并重启 Home Assistant，确认没有新增认证提示。
2. 添加集成，保留小数量上限并选择单独测试目录。
3. 调用 `run_backup` 且设置 `dry_run: true`，只核对固定状态与数量。
4. 选择没有敏感内容的时间段产生一个新事件，再执行一次正常备份。
5. 验证 MP4 可播放、音视频符合选项、状态不包含私有标识。
6. 观察至少一个每日计划周期后，再把目录作为正式备份目标。

步骤 4 和 5 已在目标环境完成；历史回填的部署、预检、正常调用、最终零待处理复核和
全部目标媒体解析也已完成。步骤 6 仍为 `UNKNOWN`，不得省略。

历史回填另按以下顺序验收：先建完整 HA 备份并保留 V0.0.2，再部署 V0.0.3；先调用
历史只读预检，随后以正常模式重复至 `history_complete: true`；最后再次只读预检并
核对新增文件均可解析、没有临时文件，且每日增量 dry-run 仍健康。

## 回退

1. 在 Home Assistant 中禁用本集成配置项，停止新的计划任务。
2. 停止 Core 后，把当前安装目录移出原位，再把保留的 V0.0.2 原安装目录恢复为
   `custom_components/xiaomi_lock_cloud_backup`；运行配置检查后再重启。
3. 如果 V0.0.2 原安装目录不可用，使用已验证的 V0.0.2 封存包或完整 HA 备份恢复；
   V0.0.1 仅作为更早的第二恢复集。
4. 已生成媒体不会在卸载时自动删除；由用户按自己的数据保留策略处理。
5. 不要通过回退操作删除 `hass-xiaomi-miot` 账号或认证存储。
6. 存储回退时先禁用本集成并确认没有运行中的下载，再移除本项目的 NFS 媒体挂载；
   如需恢复旧的本地媒体目录，应使用保留的独立回滚副本并先核对文件数量与摘要。
