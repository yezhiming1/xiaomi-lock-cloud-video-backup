# 早期云录像隔离实验归档（V0.0.1）

## 归档结论

该实验是正式集成之前的一次性可行性验证，现已退役，仅作为历史技术证据保留。
正式下载、历史回填、去重、计划任务和保留策略均由当前项目实现；不得重新部署或继续
使用本实验代码。

本文件由原实验的 README、执行状态和六份尝试/预检回执脱敏汇总而成。原始回执、真实
媒体、事件时间、尝试标识、私网地址、本机路径、设备或文件标识、云端地址及认证相关
材料均未迁入公开仓库。

## 实验目标与边界

- 目标设备型号为 `xiaomi.lock.s1`。
- 通过 `hass-xiaomi-miot v1.1.4` 已实现的 Xiaomi Smart Camera 云端路径，验证一条由
  用户专门创建的无敏感样本能否下载并封装为 MP4。
- 临时 Home Assistant 配置位于内存文件系统；临时账号、会话接收状态和解密片段不写入
  项目目录。
- 签名播放列表、录像标识、媒体地址、AES 密钥和 IV 只在运行时内存中使用；解密片段
  只进入容器临时内存盘。
- 不读取缩略图、人脸图或其他历史媒体；实验只允许一次性探测与单条下载。
- 主 Home Assistant、NAS 和其他既有服务均不挂载、不修改。

## 验证证据摘要

1. 离线和合成验证通过：主机与固定 Home Assistant `2026.8.2` 镜像中的 9 项测试覆盖
   AES-128 HLS 分片下载、逐片解密、MP4 合并、`ffprobe`、非 HLS 响应、状态头、非安全
   地址、`EXT-X-MAP` 拒绝、固定错误码和命令行隐私。
2. 第一次有效尝试在设备匹配阶段安全失败，没有进入事件或媒体下载。
3. 第二次尝试找到唯一设备和唯一候选事件，但媒体处理以固定的通用封装失败码终止，
   没有留下 MP4 或临时分片。
4. 第三次尝试再次找到同一候选，进一步把失败收窄为输入格式不可识别；没有重放已消费
   的尝试，也没有留下媒体文件。
5. 第四次改为先验证播放列表，再逐片段 AES-128-CBC 解密并合并。该次只执行一次下载，
   成功生成一条约 21.35 秒的 MP4；`ffprobe` 可解析，视频为 HEVC `1080×1920`，包含
   AAC 音轨，完整解码退出码为 0。
6. 成功样本在片段衔接处出现过少量重复 DTS 提示，因此真实客户端连续播放体验没有被
   提升为已验收结论。
7. 每次失败和最终成功均生成单独的状态回执；归档前共有 2 份预检/对账回执和 4 份尝试
   回执。公开归档只保留上述状态结论，不保留原始 JSON。
8. 实验结束后，临时容器、网络、临时页面、临时账号、会话缓冲和接收通道均已清理；
   既有 Home Assistant 服务保持可用。

## 证据等级与未覆盖范围

已证明的范围仅为：一台真实目标型号设备的一条样本，在隔离环境中完成“事件发现 →
签名 HLS → AES-128 分片解密 → MP4 合并与完整解码”。

以下内容在该实验中没有实现或没有形成有效验收证据：

- 每日自动下载与计划触发；
- 长期认证续期；
- 增量游标、去重和历史回填；
- 失败重试上限与隔离；
- 保留周期与空间不足处理；
- 长期稳定性和真实客户端连续播放；
- 其他门锁型号兼容性。

这些能力后续由正式项目另行实现和验证，不能从本次单样本实验推断。
