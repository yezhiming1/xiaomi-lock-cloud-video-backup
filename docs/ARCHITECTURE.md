# 架构与信任边界

## 数据流

1. 集成先从 `hass.data["xiaomi_miot"]["sessions"]` 的云设备列表选择目标，并在内存中
   按设备编号去重。云设备列表没有匹配时，才读取 `entities` 中已经加载的实体索引；
   实体绑定的云对象必须仍属于上述已加载会话。两条路径都不读取认证存储。
2. 用户明确选择的“经过/停留” `event.*` 实体发生有效变化后，集成按尾沿防抖 120 秒
   执行增量查询；每日 03:30 使用同一查询作为遗漏核对。显式历史回填使用独立结束游标
   向更早页面推进，不改变增量游标。
3. 设备编号和录像编号仅保存在本次调用的内存对象中；持久状态只记录
   `SHA-256(model + NUL + file_id)`。
4. 集成在内存中生成一次性签名的 HLS 地址，限制为 HTTPS，并限制重定向、
   播放列表、分片、累计下载量和最终文件大小。
5. AES-128 密钥与 IV 只在内存中使用。解密后的临时分片放在运行环境的临时目录，
   `ffmpeg` 只接收本地路径。
6. 合并后的 MP4 经 `ffprobe` 验证单视频流、时长和大小后才原子发布。
7. 每个成功项目立即写入 Home Assistant Store，降低媒体已发布但状态未提交的窗口。
8. 正常非 dry-run 把去标识运行结果追加到输出目录的固定 JSONL 状态日志，供独立本地
   消费者读取；该消费者不进入 HA Store，也不接触 Xiaomi Miot 会话。

## 持久状态

状态只包含：

- 每日增量毫秒游标；
- 历史结束游标、完成布尔值和已提交页数；
- 事件摘要；
- 每个摘要的固定失败次数；
- 本集成生成的文件名和完成时间；
- 事件摘要到已完成/待处理文件名的绑定，用于同秒无覆盖与中断恢复；
- 固定运行状态码。
- 连续基础设施失败计数和状态报告递增序号。

不保存设备编号、录像编号、事件原始响应、签名地址、密钥、账号字段或媒体内容。

## 历史回填

- `run_history_backfill` 默认串行选择至多 100 条，每次至多扫描 20 页，并与每日任务共用
  同一互斥锁。
- 历史服务不调用保留删除；清理仍只由普通增量运行执行，避免回填动作扩大为删除动作。
- 首次正常回填先冻结上边界；之后每次从持久历史游标恢复。回填期间新产生的录像继续由
  每日增量处理。
- 历史路径要求云端返回布尔型 `isContinue`。`true` 时还必须给出严格向过去移动的
  `nextTime`；空事件页不会被误判为历史结束，停滞或无效游标以固定错误码失败。
- 一页中仍有未成功或未隔离的事件时，不提交该页的下一游标。旧事件成功或第三次失败
  隔离只会对每日游标执行 `max`，因此不会倒退每日增量位置。
- `dry_run` 只在内存中有界扫描，不初始化或推进历史状态。服务响应仅包含固定状态、
  计数和布尔值，不包含时间、录像编号或云端原始字段。

该分页行为不是公开 API 合约。公开上游日志只提供观察证据：有事件的响应包含
`nextTime` 与 `isContinue`，而另一个门锁案例显示空事件数组仍可能是
`isContinue: true`。因此实现把结构缺失、游标停滞和页数上限都视为未完成，而不猜测
历史已结束。参见 hass-xiaomi-miot [事件列表示例](https://github.com/al-one/hass-xiaomi-miot/issues/278)
和[门锁空页示例](https://github.com/al-one/hass-xiaomi-miot/issues/1395)。

## 输出与清理

输出路径必须是 `/media` 下的相对 POSIX 路径。集成只创建最终叶目录，父目录必须
已经存在；这样不会把拼写错误误当成新挂载。清理只处理状态中记录且符合固定文件名
前缀的普通单硬链接文件，拒绝符号链接、目录、额外硬链接和目录逃逸。
保留天数 `0` 时跳过全部删除逻辑；这让完成远端大小与 SHA-256 校验的外部备份任务成为
唯一删除方。

新文件以事件时间转换后的北京时间秒级命名；同秒事件按确定性序号追加 `-02`、`-03`。
显式迁移服务只接受旧格式受管 MP4，要求文件集合与 Store 中的旧名集合完全一致，并以
同目录硬链接、取消旧链接、目录 `fsync` 的顺序切换；任一步失败即尝试恢复旧文件与旧状态。
该过程不读取或修改 Doorlock Sentinel 数据库，也不调用 115。

## 状态交接

`.xiaomi_lock_backup_status.jsonl` 是追加式、最多 16 MiB 的本地协议。报告键为
`SHA-256(config_entry_id + NUL + sequence + NUL + operation)`；原配置项 ID 不写入文件。
字段集合固定为 schema、source、report_key、recorded_at、state、attempts 和 error_code。
日志创建/追加使用 `O_NOFOLLOW`，并在写入前验证普通文件和单硬链接。日志失败只写固定
本地错误码，不改变已经成功的媒体备份结果。

## 失败策略

网络、云端、HLS 和媒体工具错误在边界处折叠为固定代码。原始响应、异常文本和媒体
工具标准错误不会进入日志、服务响应或持久状态。单条事件失败三次后进入隔离，避免
永久阻塞队列；该选择意味着不兼容事件可能需要人工重新处理。
